## Independent structural oracle

Use the known source `fn main() -> int32 { return 42; }`, size 33, whose real
lexer tokens are independently Fn[0,2), Main[3,7), LeftParen[7,8),
RightParen[8,9), Arrow[10,12), Int32[13,18), LeftBrace[19,20), Return[21,27),
IntegerLiteral[28,30), Semicolon[30,31), RightBrace[32,33), EOF[33,33).
Begin with this accepted stream, then make one deliberate structural mutation
per row; do not use producer-inconsistent spelling as a positive guarantee.

| Named case | Deliberate change | Exact checked outcome |
|---|---|---|
| UnknownSelectedZero | selected ID 0, any token storage | SourceError UnknownSource, selected ID, begin/end 0, absent size |
| UnknownSelectedNonzero | selected unregistered nonzero ID | Same original source_text payload |
| UnknownTokenSource | index 8 source_id unregistered, range [28,30) | Original UnknownSource for token ID/[28,30), absent size |
| KnownOtherSource | index 8 source_id is another registered identical 33-byte snapshot | SourceMismatch, selected ID, token_index 8 |
| ReversedToken | index 8 range [30,28) | ReversedRange, original ID, 30/28, size 33 |
| BeyondToken | index 8 range [28,34) | BeyondSource, original ID, 28/34, size 33 |
| UnsupportedKind | index 8 kind is initialized cast outside enumerators | UnsupportedTokenKind, index 8 |
| EmptyNonEof | index 8 range [28,28) | EmptyTokenSpan, index 8 |
| BackwardsSpan | index 8 range [18,19) | OutOfOrderOrOverlappingSpan, index 8 |
| OverlappingSpan | index 8 range [26,30) | OutOfOrderOrOverlappingSpan, index 8 |
| EmptyStorage | known selected source, no tokens | MissingEndOfFile, absent index |
| MissingFinalEof | remove final EOF, retain eleven real tokens | MissingEndOfFile, absent index |
| EarlyEof | index 1 becomes EOF while later tokens remain | NonFinalEndOfFile, index 1 |
| DuplicateEof | append a second valid EOF | NonFinalEndOfFile, index 11 |
| TokenAfterEof | append initialized real token after existing EOF | NonFinalEndOfFile, index 11 |
| NonemptyFinalEof | final EOF range [32,33) | InvalidEndOfFileSpan, index 11 |
| EofBeforeSourceEnd | final EOF range [32,32) | InvalidEndOfFileSpan, index 11 |
| ReversedEof | final EOF [33,32) | Original ReversedRange with size 33 |
| BeyondEof | final EOF [34,34) | Original BeyondSource with size 33 |

For each row assert selected versus offending IDs correctly, every SourceError
field, stream kind/index, no ParsedSmokeEntry alternative, zero appended
diagnostics, unchanged prior initialized diagnostic fields/order/Error state.
SourceError is not translated to TokenStreamError. Test supported Invalid
explicitly so an implementation's supported-kind check cannot omit it.

Combined-fault rows independently prove the exact 04-01 precedence:

- Unknown selected source with empty storage or bad token wins at selected lookup.
- Unknown token ID plus reversed range/unsupported kind returns UnknownSource;
  known other-source reversed range returns that source's ReversedRange before
  SourceMismatch; known other-source plus unsupported kind returns SourceMismatch.
- Reversed-and-beyond range returns ReversedRange; valid same-source empty span
  plus unsupported kind returns UnsupportedTokenKind before EmptyTokenSpan.
- Nonfinal EOF with in-bounds wrong shape returns NonFinalEndOfFile; source-invalid
  EOF preserves its SourceError before finality. Wrong-shape final EOF before the
  previous token's end returns InvalidEndOfFileSpan before order/overlap.
- Two bad token indices return the earlier index, even if the later fault has a
  higher same-index check. Existing-token failure precedes MissingEndOfFile.
- Real lexer Invalid before a later reversed/beyond span, nonfinal EOF or invalid
  final EOF still yields the later structural failure, with lexical diagnostics
  preserved and no parser additions. Potential first syntax mismatch before a
  later structural fault likewise yields infrastructure failure without syntax.
- Structurally valid Invalid at the beginning, within and after a complete entry
  returns LexicalErrors, including an intentionally isolated empty engine, proving
  that Invalid gating does not depend on earlier engine Error count.

Positive structural controls use actual lexer streams: punctuation adjacency,
whitespace gaps, a known-source EOF-only empty stream and whitespace-only EOF.
The latter two produce exactly one Fn syntax Error at actual EOF, not MissingEOF.
Also include a bounded long stream with a malformed final token to prove full
checking before early syntax rejection, without timing assertions or new quotas.
