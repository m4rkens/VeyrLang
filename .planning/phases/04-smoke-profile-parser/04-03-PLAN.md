## Required integration fixtures

Use real lex → parse calls without mocks, generated production-oracle data or
parser-internal lexer invocation. Expected spans/messages/locations below are
literal independent oracles, not values calculated from parser output.

1. **Owned result and tight original bounds:** For source bytes
   `\tfn main() -> int32 {\r\nreturn 00042;\r\n}\n`, size 40, require entry [1,39),
   return [23,36), integer [30,35). The same original bytes resolve after caller
   strings, LexResult wrapper, input token vector and local engine are destroyed;
   copy/move the saved value and add 3,000 fresh same-name/other-name registrations
   while retaining the originating SourceManager. Assert original selected ID,
   exact text, unchanged spans and distinct later registration IDs. Do not access
   any object after its required lifetime or promise cross-manager provenance.
2. **Semantic independence:** Real lex/parse accepts 0, 42, 255, 256, 00042 and
   a 16,384-digit decimal token; retain literal text/span only. Surrounding and
   internal accepted whitespace, punctuation adjacency and trailing CR/LF bytes
   preserve tight bounds. No numeric field or conversion is introduced.
3. **Lexical handoff:** Invalid before/within/after an otherwise complete entry,
   including unsupported signs/nondecimal numbers, comments, high bytes, NUL and
   exact `/*/return` boundary. That last source retains Invalid [0,9), EOF [9,9)
   and its single existing lexical Error. Copy all diagnostic fields before
   parse, then require LexicalErrors/no value and byte-for-byte unchanged owned
   messages/labels, spans, order, duplicates and Error state. A syntax mismatch
   before a later Invalid still emits no parser Error. Do not rerun the lexer's
   entire all-byte suite here; preserve its accepted cases as regression.
4. **Accumulated engine and duplicate syntax:** Preseed explicitly initialized
   Note/Warning/Error with distinct owning data; parse clean independent syntax
   and require a complete value plus unchanged prior fields/has_errors. Demonstrate
   in test-local consumer logic that value plus prior Error cannot qualify for a
   later successful handoff; expose no compiler-success API. Parse the same
   malformed syntax twice and require exactly two appended identical parser
   Errors in order, no partial value and no deduplication. Reacquire views after
   every emission. Also show Note/Warning alone do not set has_errors.
5. **EOF/locations/one opener:** Real missing-body-closer sources below each emit
   exactly `expected '}', found end of source in M1 Experimental Smoke Profile`,
   severity Error and related [19,20) labelled `opening '{' is here` at line 1,
   column 20. Primary is the exact EOF range indicated:

   | Original bytes | Size / primary | EOF location |
   |---|---|---|
   | `fn main() -> int32 {\n return 42;\n` | 33 / [33,33) | 3:1 |
   | `fn main() -> int32 {\r\n return 42;\r\n` | 35 / [35,35) | 3:1 |
   | `fn main() -> int32 {\r return 42;\r` | 33 / [33,33) | 1:34 |

   Missing-paren prefixes `fn main(\n`, `fn main(\r\n`, `fn main(\r` use EOF
   9/10/9 and locations 2:1/2:1/1:10, exactly one opener [7,8) at 1:8 and label
   `opening '(' is here`. Empty input uses [0,0), 1:1 and no related opener;
   whitespace-only `\t \r\n` uses [4,4), 2:1, no related. Missing semicolon before
   a real `}` retains its whole token and no opener context. Existing
   LF/CRLF/lone-CR rules are consumed, not reimplemented.
6. **Separate owning rendering:** Render actual owning parser Error copies for
   missing `)`/`}` and the real-token missing-semicolon case using the existing
   PlainTextRenderer. Use lexically valid source with hostile display-name bytes
   (ESC, embedded NUL and high bytes), not a lexical failure masquerading as
   syntax. Assert literal complete rendered output for at least the two closer
   fixtures, including escaped display metadata, original locations and one
   related opener; all emitted messages/labels remain fixed M1 wording. Assert
   output has only supported ASCII plus LF, retains ownership after temporary
   diagnostic/engine destruction and never clears engine Error state. Compare
   raw parser fields separately from rendering. Do not change clipping,
   unsupported severity handling or other deferred renderer hardening.
