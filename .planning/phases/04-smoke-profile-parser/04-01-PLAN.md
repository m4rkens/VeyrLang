## Exact checked-input and failure contract

Adopt the research recommendation as this plan's precise implementation detail
under D-11; this is not an additional language decision:

| Priority | Check | Failure |
|---|---|---|
| 0 | Resolve selected source with sources.source_text before inspecting tokens | Exact original SourceError |
| 1 | In increasing token index, sources.validate(token.span) first | Exact original SourceError, with token ID/range/optional size |
| 2 | Checked token source equals selected source | SourceMismatch at that index |
| 3 | Explicit supported-kind switch over all thirteen TokenKind enumerators | UnsupportedTokenKind at that index |
| 4a | EOF must be the final token | NonFinalEndOfFile at that index |
| 4b | Final EOF has begin == end == original source_size | InvalidEndOfFileSpan at that index |
| 4c | Non-EOF has begin &lt; end | EmptyTokenSpan at that index |
| 5 | After the first token, current.begin &gt;= previous.end | OutOfOrderOrOverlappingSpan at that index |
| 6 | After per-token validation, a last token exists and is EOF | MissingEndOfFile with absent token_index |
| 7 | Only after the whole stream passes, reject any remembered Invalid | ParseRejected{LexicalErrors} |
| 8 | Otherwise match the fixed sequence below | First mismatch emits one Error and returns ParseRejected{SyntaxError} |

An earlier structural error index wins, and the listed checks order faults at
the same index. SourceManager's own UnknownSource → ReversedRange → BeyondSource
precedence and payloads survive unchanged. Nonfinal EOF wins over its own
otherwise in-bounds wrong shape, but checked source failure precedes both.
Missing EOF comes after all existing-token checks. Empty token storage is
infrastructure failure; a real EOF-only empty source is incomplete syntax.
Valid adjacency and gaps are allowed. No checking of keyword bytes, token
spelling width, integer digits or omitted-gap whitespace is selected (D-16).

Infrastructure and lexical rejection append no diagnostic and expose no value.
Remember Invalid and continue structural checking; a later structural fault wins
over any earlier Invalid or potential syntax mismatch. SourceManager and engine
are never reset. An earlier engine Error does not block a valid independent
stream (D-09); any accumulated Error still forbids later compilation success.
