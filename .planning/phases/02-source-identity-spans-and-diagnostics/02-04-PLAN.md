## Artifacts this phase produces (this plan)

- `plain_text_renderer.hpp/.cpp`: stateless `PlainTextRenderer::render(const Diagnostic&, const SourceManager&) const -> RenderResult`; `RenderResult = std::variant<std::string, RenderError>`; `RenderError { SourceError source_error; std::optional<std::size_t> related_index; }` (null index means invalid primary, otherwise exact related index). Returned text is owned, terminated by LF; no streams, console, filesystem, color, LLVM or output-delivery API. C++ allocation failures retain ordinary C++ semantics, not a language OOM decision.
- Header layout proposal: primary present => `escaped-name:line:column: severity: escaped-message\n`; absent => `severity: escaped-message\n`. Lowercase severity words. Every related span follows in input order as `note: escaped-label (escaped-name:line:column)\n`, even for a primary-less diagnostic; no invented primary/excerpt. With no spans, only the message header is produced. Related locations remain supplemental, not a substitute primary.
- Escape proposal: source excerpts/messages/labels/display names preserve printable ASCII (including ordinary path backslashes, case, spaces and separators); TAB/CR/LF become visible `\t`/`\r`/`\n`, remaining control/DEL/high bytes become uppercase `\xHH`. Stored names and bytes remain exact; byte escaping is presentation, not canonicalization or accepted encoding. No actual input control/ANSI sequence is emitted. Each source byte gets an explicit rendered-cell interval so byte columns never become visual columns.
- Fixed excerpt proposal: at most 3 source lines, at most 80 original bytes per line, at most 320 escaped cells plus gutters/clipping markers per excerpt row. Start at the primary location's containing line; first-line byte window starts at max(0, local_begin-40) and covers at most 80 bytes; subsequent intersecting lines start at column 1. Include original terminator bytes as visible escapes. Add `...` at clipped horizontal edges and a standalone `...` line when further span lines remain. A span ending exactly at the next line start excludes that next line; an empty span renders only its containing line.
- Rows use `line | escaped-bytes\n` followed by `spaces-for-line-digits | marker-padding^~~~\n` for the visible highlighted cell interval. Caret marks first selected visible cell, tildes the remaining visible cells; on each rendered span line. Zero-width/interior/EOF gets one caret at the byte-boundary cell, including empty-source/final-empty-line EOF. Underline construction is capped by visible cells before allocation. Clipping is presentation only: preserve true header location/span, never return a clamped source range.
- Add renderer source to veyrcore and renderer test source to existing diagnostic_tests. `PlainTextDiagnostic.*` covers exact strings plus independent clipping/escape invariants; no golden-file framework, source file loader or driver integration.
